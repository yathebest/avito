# Ориентация текста в кропах

Для каждого изображения нужно оценить `p_180` — вероятность того, что текст перевёрнут. Балл считается как `1 − Brier Score`.

В репозитории я оставил быстрый вариант на PaddleOCR. Именно его запускает `main.ipynb` и именно им получен итоговый `submission.csv`.

| Вариант | 20 000 кропов | 1 − Brier на Stepik | Brier |
| --- | ---: | ---: | ---: |
| Классификатор ориентации | около 4 минут | **0,95944706** | 0,04055294 |
| Классификатор вместе с распознаванием текста | около 40 минут | **0,98809114** | 0,01190886 |

Более точный вариант я запускал отдельно. Его кода и весов здесь нет; ноутбук в этом репозитории воспроизводит результат первой строки. Время зависит от компьютера: в Docker быстрый вариант прошёл за 5 минут.

## Запуск

Понадобятся Docker и тестовые данные. Распакованный набор должен лежать в `test_data/`: файл `sample_submission.csv` и изображения в `test/images/`. Вместо папки можно положить в корень проекта исходный `test.zip`. Веса классификатора уже лежат в `models/`.

Из корня проекта в PowerShell:

```powershell
docker build -t avito-orientation .
docker run --rm --network none --mount "type=bind,source=$($PWD.Path),target=/work" avito-orientation
```

На Linux во второй команде замените `source=$($PWD.Path)` на `source=$(pwd)`. Сборка образа устанавливает зависимости. При запуске виден прогресс обработки, а в корне проекта появляется `submission.csv` с 20 000 строками в порядке `sample_submission.csv`. Если Docker не нужен, можно установить `requirements.txt` и выполнить `main.ipynb`.

## Модель и проверка

Основа быстрого варианта — открытая модель PaddleOCR `PP-LCNet_x1_0_textline_ori`. Я прогоняю каждый кроп дважды: без изменений и с поворотом на 180°. Затем объединяю вероятности по формуле `sigmoid((logit(p0) − logit(p180)) / 2)`. Это TTA одной модели, а не ансамбль разных сетей.

Сначала я сделал синтетический набор из русских и латинских надписей: 30 000 прямых кропов для обучения и 2 000 для проверки, плюс повёрнутая копия каждого. MobileNetV3-Small набрала на нём 0,99837, но на реальных кропах до дообучения — только 0,70384. Синтетики для этой задачи оказалось мало.

Затем использовал [HierText](https://github.com/google-research-datasets/hiertext). Из train подготовил 40 000 пар 0°/180°, из официального validation — 3 000 пар. Исходную ориентацию определял по геометрии строк и порядку слов, без ручной разметки. При проверке фотографии не пересекались между частями выборки. После дообучения MobileNetV3-Small получила 0,92319 по `1 − Brier`, один проход PaddleOCR — 0,93908, их взвешенная смесь — 0,95551. Два прохода PaddleOCR дали 0,98424 на той же проверке.

Ещё я пробовал распознавать текст на обоих поворотах моделью PaddleOCR `eslav_PP-OCRv5_mobile_rec` и объединять этот результат с классификатором. Получилось 0,99409 на псевдоразмеченной проверке HierText и 0,98809114 на Stepik. Вес распознавателя подбирал по HierText, не по тесту Avito. Этот вариант точнее, но работает примерно в десять раз дольше, поэтому в репозитории оставил быстрый.

Файлы ORB-en/SROIE в Parquet я тоже смотрел как возможные источники данных, но в обучении и итоговом инференсе их не использовал. Локальная проверка на HierText отличается от теста Avito; результаты Stepik указаны отдельно в таблице выше.

## Что ещё пробовал

Калибровку и дополнительные проходы я проверял на 6 000 кропах HierText. Разбивал данные на пять частей по исходным фотографиям. Для сравнения: базовые два прохода дали 0,98424 по `1 − Brier`, а округление вероятностей до 0/1 — 0,97933.

Температура 1,8 снизила балл до 0,98116, сдвиг вероятностей на 10% к 0,5 — до 0,98163, ограничение диапазоном [0,02; 0,98] — до 0,98394. Температура около 0,95 добавила лишь 0,00002. Дополнительный проход с контрастом +10% дал 0,98409, с яркостью +10% — 0,98412, с горизонтальным отражением — 0,98013. Для этих трёх преобразований вес дополнительного прохода был 0,5.

Яркость −10% и контраст −10% оказались чуть лучше: 0,98435 и 0,98432 на групповой кросс-валидации. Прирост около 0,0001 требует третьего прохода для каждого изображения. Проверял и вторую компактную модель [PP-LCNet_x0_25_textline_ori](https://www.paddleocr.ai/main/en/version3.x/module_usage/textline_orientation_classification.html): она добавила около 0,00066 на HierText, но тоже увеличила время обработки. На Stepik эти изменения я не проверял, поэтому итоговый CSV оставил без них.

В `main.ipynb` задан `SEED = 20260925`; случайных преобразований при инференсе нет. Для синтетики использовал seed 20260925, для обучения на HierText — 20260926. Тестовые изображения вручную не размечал, внешние API и большие языковые модели не использовал. Открытые компоненты: [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR), [PaddlePaddle](https://github.com/PaddlePaddle/Paddle), NumPy и Pillow; в экспериментах также PyTorch/torchvision и HierText. Версии зависимостей для итогового запуска указаны в `requirements.txt`.
