# Ориентация текстовых кропов

Для каждого кропа нужно предсказать `p_180` — вероятность поворота текста на 180°. Метрика задания: `1 − Brier Score`. Финальная сдача здесь — **быстрый CPU-вариант**.

| Вариант | Время на 20 000 кропов | 1 − Brier на Stepik | Brier |
| --- | ---: | ---: | ---: |
| Классификатор ориентации, два поворота | около 4 минут | **0,95944706** | 0,04055294 |
| Классификатор + распознавание текста, два поворота | около 40 минут | **0,98809114** | 0,01190886 |

Время зависит от компьютера: контрольный запуск быстрого варианта в Docker занял 5 минут. Время второго варианта приведено по отдельному прогону. Его код и веса не входят в текущую версию репозитория; отправлять CSV с баллом 0,98809114 вместе с этим кодом нельзя — он его не воспроизводит.

## Как запустить финальный вариант

Нужны Docker и тестовый набор: `test_data/sample_submission.csv` и `test_data/test/images/*.png`. Можно положить в корень исходный `test.zip` вместо распакованного набора. Веса модели уже в `models/`.

Из корня проекта в PowerShell:

```powershell
docker build -t avito-orientation .
docker run --rm --network none --mount "type=bind,source=$($PWD.Path),target=/work" avito-orientation
```

На Linux во второй команде используйте `source=$(pwd)`. Первая команда скачивает и устанавливает зависимости, вторая создаёт `submission.csv` с 20 000 строками в порядке `sample_submission.csv`. Время этапов сохраняется в `results/executed.ipynb`. Можно выполнить `main.ipynb` и без Docker после установки `requirements.txt`.

## Что делали

Быстрый вариант использует предобученную открытую модель PaddleOCR `PP-LCNet_x1_0_textline_ori`. Один и тот же кроп подаётся ей как есть и после поворота на 180°. Результаты двух проходов объединяются как `sigmoid((logit(p0) − logit(p180)) / 2)`. Это ансамблирование двух ракурсов **одной модели** (TTA), а не двух разных сетей. Пороговое округление до 0/1 ухудшило Brier на своей проверке: 0,97933 против 0,98424 у вероятностей.

Для экспериментов использовали:

- Собственный синтетический набор из русских и латинских надписей: 30 000 прямых кропов для обучения и 2 000 для проверки, к каждому добавлен поворот на 180°. MobileNetV3-Small получила 0,99837 на этой синтетической проверке, но только 0,70384 на реальных кропах до дообучения.
- [HierText](https://github.com/google-research-datasets/hiertext): из строк train сделали 40 000 пар 0°/180°, из отдельного официального validation — 3 000 пар. Исходную ориентацию определяли по геометрии и порядку слов; это **псевдоразметка**, а не ручная проверка меток. При валидации разделяли по исходным фотографиям. После дообучения MobileNetV3-Small набрала 0,92319 по `1 − Brier`; одиночный проход PaddleOCR — 0,93908; их взвешенная смесь — 0,95551 на отложенной части. Финальные два прохода PaddleOCR дали 0,98424 на своей проверке.
- Более медленное сочетание того же классификатора с распознавателем PaddleOCR `eslav_PP-OCRv5_mobile_rec` на **обоих поворотах каждого кропа**: 0,99409 на псевдоразмеченной проверке HierText и 0,98809114 на Stepik. Коэффициент объединения подбирали на HierText, не на тесте Avito.

Файлы ORB-en/SROIE в Parquet также изучали как кандидатов для данных, но в перечисленных результатах и финальном инференсе они не использовались. Своя проверка отличается от теста Avito; для сравнения финальных вариантов выше приведены баллы Stepik.

В финальном ноутбуке стоит `SEED = 20260925`; инференс не содержит случайных преобразований. При подготовке синтетики использовали seed 20260925, при обучении на HierText — 20260926. Тестовые изображения вручную не размечались. Внешние API и большие языковые модели не используются. Открытые компоненты: [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR), [PaddlePaddle](https://github.com/PaddlePaddle/Paddle), NumPy и Pillow; в экспериментах также PyTorch/torchvision и HierText. Версии зависимостей финального запуска зафиксированы в `requirements.txt`.
